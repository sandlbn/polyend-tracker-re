# OpenTracker desktop simulator

Runs the same platform-independent core (`src/core/**`, unchanged) as the
device firmware, on Linux, with host implementations of the HAL interfaces in
`src/core/hal_api.h`. Nothing in `src/core` or `src/hal` is modified for it.

## Build and run

Needs a host `g++` (C++17), SDL2 (`pkg-config sdl2`) and optionally ALSA
(`pkg-config alsa`) for MIDI.

```
make -C reimpl sim                 # or: make -C reimpl/sim
reimpl/build/sim/opentracker-sim   # opens the window
make -C reimpl/sim check           # headless smoke test -> build/sim/smoke*.png
```

`check` first runs `build/sim/jpeg-check` (sources in `check/`): it loads
`fixtures/cover.jpg` through `SwDisplay::loadJpeg` into the RAM_G model at the
cover address (spec 13 §I.3), draws it with `drawImage` and checks the pixels and
the rejections (progressive, size limits). JPEG decode on the host uses the
vendored `third_party/stb_image.h` (public domain / MIT, `STB_IMAGE_LICENSE.txt`).

Options:

| option | meaning |
|---|---|
| `--sd DIR` | SD card root folder (default `~/.opentracker-sd`, created on first run) |
| `--scale 1\|2` | window scale (the window is also resizable) |
| `--line-in` | open the default capture device as line-in (off by default) |
| `--line-in-tone HZ` | synthetic line input (tone bursts), e.g. to test the Sample Recorder headless |
| `--no-audio` / `--no-midi` | skip the audio device / ALSA ports |
| `--demo` | renderer and input demo instead of the app |
| `--quit-after MS` | exit after MS milliseconds |
| `--script FILE` | headless: replay a script (see below) |
| `--screenshot OUT.png` | headless: save the framebuffer when the script ends |
| `--panel` | screenshots show the whole front panel, not only the 800x480 screen |
| `--wav OUT.wav` | headless: record the rendered audio |
| `--instant-display` | show every frame at once (also `OT_SIM_BUSY=0`). Default: FT81x frame pacing -- a frame is uploaded, then shown at the next 54 Hz vsync, `frameReady()` false meanwhile |

The workspace is autosaved to the SD folder when the window closes.

## Front panel and key map

The window shows the 800x480 screen (upright; the device's 180° `REG_ROTATE`
is not applied), the 8 screen buttons F1..F8 under it, the 12x4 pad grid
(lit from `ILeds`), the encoder and the 5x5 key block, where key
`id = 8 + row*5 + col` as in the keypad matrix (spec 05 §2.1.1, names from
spec 06 §0.2), plus Aux and Help. The physical arrangement is approximate;
the button ids are the canonical ones from `src/core/ui/buttons.h`.

Mouse: left click/hold on any control presses it, release releases it.
Right-click a button to latch it down (e.g. Shift) and again to release it.
Click the left/right half of the encoder ring to turn it one detent, the
centre for encoder push; the mouse wheel turns the encoder.

Keyboard (scancodes, so it works the same on any layout). Tab or Caps Lock
toggles between COMMAND and PAD mode (shown in the panel status).

Always:

| key | control |
|---|---|
| F1..F8 | screen buttons 0..7 |
| F9 / F10 / F11 / F12 | Pattern / Song / Aux / Help |
| Print Screen / Pause | Power switch (Shift + Power = screenshot to Snapshots/) |
| arrows | Up / Down / Left / Right (auto-repeat like the device) |
| Shift (either) | Shift |
| Space | Play |
| Insert | Insert |
| Delete, Backspace | Delete |
| Enter | encoder push |
| Page Up / Page Down, mouse wheel up / down | encoder +1 / -1 (on lists the wheel is flipped: wheel down moves down the list) |
| Ctrl+Q | quit |

COMMAND mode (default):

| key | control |
|---|---|
| R | Rec |
| C | Copy (Shift+C = paste) |
| `[` / `]` | encoder -1 / +1 |
| N / I / X / V | Note / Instr / Fx1 / Fx2 |
| P | Pattern |
| A / H | Aux / Help |
| 1 2 3 4 5 | Instrument Params, Performance, File, Config, Master |
| 6 7 8 9 0 | Sample Loader, Sample Playback, Sample Editor, Sample Recorder, Song |

PAD mode (letter and digit rows play the pads, velocity 100; pad 0 is top-left):

| keys | pads |
|---|---|
| `1 2 3 4 5 6 7 8 9 0 - =` | row 0: pads 0..11 |
| `Q W E R T Y U I O P [ ]` | row 1: pads 12..23 |
| `A S D F G H J K L ; ' \` | row 2: pads 24..35 |
| `Z X C V B N M , . /` | row 3: pads 36..45 (46 and 47: mouse only) |

Hold ticks for buttons come from the app's own timing (`Ui::update`), as on
the device; the auto-repeat ids (0x19..0x1b, 0x1e..0x21) re-send presses with
the spec 05 §2.1.1 timing (333 ms, then accelerating), generated by the
simulator's input driver like the device driver does.

## Headless scripts

With `--script` (or `--screenshot`) no window or audio device is opened. Time
is virtual: every simulated millisecond runs one app loop pass, and a
128-frame audio block is rendered every 128/44100 s, so runs are
deterministic. 300 ms are simulated before the script starts (boot), 50 ms
after it ends. Script lines (`#` starts a comment):

```
wait MS                     advance time
press NAME / release NAME   button down / up
tap NAME [MS]               press, wait MS (default 60), release, wait 60
hold NAME [MS]              press, wait MS (default 600), release
pad N down|up|tap [VEL]     pad 0..47
enc DELTA                   encoder detents (+ = clockwise)
screenshot FILE.png         save the framebuffer now (--panel: whole panel)
panelshot FILE.png          save the whole front panel now
usbstorage on|off           2.x USB Storage mode on / off (interface event 10; Config >
                            USB > USB Storage): the sim has no USB, the card directory is
                            locked while the mode is on
usbhost none|waiting|inuse|ejected
                            what the simulated computer does with the drive (mode page line,
                            eject reminder on Exit while "inuse")
expect-usbstorage on|off    fail unless the mode, its page and the card lock all match, or if
                            the app touched the locked card
expect-usbwarn on|off       fail unless the eject reminder is (not) shown
theme N / font N            config Display theme 0..2 / Display font 0..1 (no Config key flow)
echo TEXT                   print to stderr
budget-reset                start a display-budget window
budget NAME WORDS           fail if a frame since the reset uploaded > WORDS
                            display-list words (or RAM_DL > 2000); a screen at
                            rest is redrawn until its fragments are cached
fragcheck NAME              fail unless the screen is pixel-identical with
                            cached fragments off and on
expect-open-ok              fail unless the last project job ended without
                            errors, no popup is open and no notice other than
                            "Project opened" was shown since the last check
expect-project NAME         fail unless the current project is NAME
expect-playing              fail unless the sequencer is playing
expect-sound N              fail if the output peak since the last
                            expect-sound / sound-reset is below N (0..32767)
sound-reset                 restart the output peak
```

Button names: `F1`..`F8`, the panel labels or `INSTRPARAMS PERFORMANCE FILE
CONFIG MASTER SAMPLELOADER SAMPLEPLAYBACK SAMPLEEDITOR SAMPLERECORDER SONG NOTE
INSTR FX1 FX2 PATTERN PLAY COPY INSERT UP DELETE REC SHIFT LEFT DOWN RIGHT
ENCPUSH AUX HELP POWER`, or a numeric id (`0x17`). Example: `scripts/smoke.txt`.

```
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy build/sim/opentracker-sim \
    --sd /tmp/sd --script sim/scripts/smoke.txt --screenshot out.png
```

Key-flow and redraw-rate checks (`make check` runs `scripts/keyflow.txt`):

```
expect-screen NAME          fail unless the active screen is NAME (e.g. Performance,
                            Sample Recorder)
expect-master PAGE SUB      fail unless Master is active on PAGE (0 Master, 1 Track
                            Mixer, 2 Global Mixer) and sub-page SUB (0 main, 1 Reverb,
                            2 Delay, 3 Limiter, 4 EQ)
fps-reset / expect-fps N    fail if fewer than N frames/s were rendered since fps-reset
tone-sample SLOT FRAMES [stereo]
                            write a test WAV (stereo: a drum-like loop) to the card, import it into SLOT (1-based)
                            and make it the current instrument
expect-playhead on|off      fail unless Sample Playback does (not) draw its playhead
```

## HAL mapping

| interface | simulator |
|---|---|
| `IDisplay` | `src/sw_display.*`: software FT81x renderer (see below) |
| `IAudioOut` | `src/sdl_audio.*`: SDL2 audio, 44100 Hz stereo int16, 128-frame blocks pulled on the SDL audio thread |
| `IStorage` | `src/host_storage.*`: host folder as card root, case-insensitive lookups like FAT, max 32 open files |
| `IMidiPort` | `src/host_midi.*`: ALSA sequencer client "OpenTracker", ports "OpenTracker DIN" / "OpenTracker USB" (connect with `aconnect` or a DAW); null port without ALSA |
| `IInput` | `src/host_hal.*`: event queue from mouse/keyboard/script |
| `ILeds` | `src/host_hal.*`: pad colours shown on the panel after `show()` |
| `IClock` | `src/host_hal.*`: `std::chrono::steady_clock` (virtual in headless mode) |

The display renderer interprets the subset exposed by `IDisplay` with the
public FT81x programmer-guide semantics: CLEAR_COLOR_RGB, CLEAR (scissored),
COLOR_RGB / COLOR_A with SRC_ALPHA blending, LINE_WIDTH and POINT_SIZE (radii
in 1/16 px), SCISSOR_XY/SIZE, BEGIN POINTS / LINES / LINE_STRIP /
EDGE_STRIP_R/L/A/B / RECTS (rounded by the line width) / BITMAPS (ROM font
handles and the custom L4 font / icon handles), VERTEX2F / VERTEX2II,
VERTEX_TRANSLATE_X, BITMAP_TRANSFORM_A..F and BITMAP_SIZE on the custom
handles, SAVE/RESTORE_CONTEXT, CMD_GRADIENT, CMD_TEXT (OPT_CENTERX/Y,
OPT_RIGHTX) and CMD_NUMBER (signed, zero-padded digit count). Unsupported
input is logged once to stderr. The custom UI fonts (spec 20 §2) are the
generated RAM_G image `src/core/ui/fonts/font_data.inc`, uploaded into the
simulator's RAM_G model exactly like on the device and drawn from there
(alpha = nibble x 17). The ROM fonts 16..31 are approximated at the FT81x
cell heights by glyphs rasterised from DejaVu Sans / Sans Mono
(`third_party/rom_fonts.inc`, generated by `../tools/fonts/gen_fonts.py rom`;
licence in `third_party/DEJAVU_LICENSE.txt`).
Screenshots use a small PNG writer written for the simulator (`src/png.cpp`,
uncompressed deflate, so files are ~1 MB).

## Limitations

- Sample rate: the device codec runs at 44117.6 Hz (spec 01 §5); the
  simulator plays at 44100 Hz, so pitch and tempo are 0.04 % lower.
- Driver-level behaviour is not simulated: FT81x display-list size limits
  (RAM_DL 2048 words) and coprocessor timing, SD card timing and errors /
  card removal, I2C keypad scanning, encoder acceleration in the driver, LED
  refresh rate, power switch, USB, firmware update, SDRAM limits.
- ROM-font metrics are approximations, so text in ROM fonts differs slightly
  from the device; the custom fonts are pixel-identical data.
- Line-in (`--line-in`) is captured and fed to the audio engine (level,
  mute and delay/reverb sends from the project); it is silent while the
  project's line-in mute is on (the default).
- Panel layout and key labels are approximations of the real hardware.
